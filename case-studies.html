Client

NovaBank Global

Role

Accessibility & Theme Architecture

Impact

100% WCAG AA Pass Rate

The Challenge

NovaBank's enterprise dashboard was heavily reliant on color to convey critical financial states (e.g., red for loss, green for profit). Furthermore, their "dark mode" was a simple CSS invert that resulted in eye-straining contrast ratios (as low as 2.1:1 in some data tables), making it unusable for users with visual impairments.

Solution Architecture

I completely refactored their CSS variables into a semantic token system. Instead of hardcoding colors, I created contextual tokens like --color-status-error-bg.

/* Refactored Token System */
:root {
  --surface-base: #ffffff;
  --text-critical: #d92d20; /* Ratio: 5.1:1 */
}

[data-theme="dark"] {
  --surface-base: #0f172a;
  --text-critical: #fca5a5; /* Ratio: 7.2:1 */
}

Colorblindness & Semantics

To solve the color-reliance issue, I introduced iconography and pattern fills to financial charts. Positive trends were accompanied by an upward arrow icon aria-hidden="true", and negative trends utilized a textured fill alongside the color red, ensuring Deuteranopia users could distinguish the data points immediately.

Client

RetailHub Global

Role

Accessible UI Engineering

Impact

40% Mobile Checkout Bounce Reduction

The Challenge

RetailHub's mobile checkout flow suffered from a high shopping cart abandonment rate. Critical accessibility bugs included a form validator that relied exclusively on red border highlights to mark errors (violating WCAG 1.4.1), and custom dropdown selectors that could not be focused or controlled by keyboard users (violating WCAG 2.1.1).

Solution Architecture

I refactored all e-commerce form input fields. Standard validation errors were accompanied by textual helper prompts mapped explicitly to input containers via aria-describedby attributes. In addition, I replaced custom selector elements with native, accessible select elements styled cleanly to blend with their custom design system.

/* Accessible Form Styling */
.checkout-input {
  border: 1px solid var(--border-color);
  transition: border-color 0.2s, box-shadow 0.2s;
}
.checkout-input:focus-visible {
  outline: 3px solid var(--primary);
  outline-offset: 1px;
}
.checkout-input.invalid {
  border-color: var(--text-critical);
}

Focus Indications & Screen Reader Help

To resolve state feedback blocks, the checkout validation system was wired up to an aria-live="polite" region, notifying users immediately of checkout validation updates. In addition, I ensured all custom focus outlines met the minimum APCA high-contrast requirement, so visually impaired keyboard users could see which element they were selecting.

Client

CareFlow Health Systems

Role

Screen Reader & Focus Management Architecture

Impact

100% Keyboard Accessible (Zero Traps)

The Challenge

CareFlow's patient health portal features complex charts, data grids, and interactive patient schedule modals. Keyboard users frequently got trapped inside interactive calendar modals (violating WCAG 2.1.2), and low-contrast or hidden focus rings made visual tracking impossible for non-mouse navigators.

Solution Architecture

I developed custom vanilla JavaScript focus-trap utilities for calendar modals and popups to ensure focus remains contained when open. In addition, I created invisible bypass links (`skip to main content`) and mapped accessible row-column relationships onto health tables.

// Custom Focus Trap Logic
function trapFocus(modalNode) {
  const focusables = modalNode.querySelectorAll('button, href, input');
  const first = focusables[0];
  const last = focusables[focusables.length - 1];
  modalNode.addEventListener('keydown', (e) => {
    if (e.key === 'Tab') {
      if (e.shiftKey && document.activeElement === first) {
        last.focus(); e.preventDefault();
      } else if (!e.shiftKey && document.activeElement === last) {
        first.focus(); e.preventDefault();
      }
    }
  });
}

Tab Flow & APCA Focus Outlines

I added custom high-contrast focus outlines styled with CSS Custom Properties using `focus-visible`. This allowed mouse users to experience standard click actions without visual distraction, while providing high-contrast rings to keyboard users. Data grids were restructured using proper header scoping (`scope="col"` and `scope="row"`).
